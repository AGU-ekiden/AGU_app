# Evernote → Notion カルテ移行パイプライン

数百人分のEvernoteカルテを、Claude Codeの利用枠（5時間/週制限）や
Notionページ作成のたびの許可プロンプトを消費せずにNotionへ移行するためのスクリプト群です。

Evernoteのエクスポート形式によって、使うパーサーが異なります。**どちらか実際に手元で
エクスポートしてみて出てきた形式に合わせて選んでください**（両方試して構いません）。

| エクスポート形式 | 対応パーサー | LLM分類 |
|---|---|---|
| 複数ノートをまとめた **HTML形式**（`ノートブック名.html` + `ノートブック名 files/`フォルダ） | `parse_html_export.py` | 不要（表形式のセルをそのまま抜き出すだけ） |
| **Evernote XML形式 (.enex)** | `parse_enex.py` → `classify.py` | 必要（フリーテキストの段落をAnthropic APIで分類） |

実際に確認したところ、トレーナーは「①②③…をセッション列、Date/担当/場所/主訴/状態/実施内容/training/memoを行」
とする**表**でノートを書いていました。この形式ならHTMLパーサーがセルの値をそのまま抜き出すだけで済み、
LLMによる分類が一切不要（＝文字化けのリスクも無く、Anthropic APIの利用料もかからない）です。
まずは対象者を1人分だけHTMLエクスポートしてみて、同じ表形式になっているか確認することをおすすめします。

## 全体の流れ（HTML形式の場合・推奨）

```
①Evernoteから「複数ノートをHTML形式で」エクスポート
        ↓
②parse_html_export.py — 表のセルをそのまま抽出し、分類済みJSONを直接出力 (LLM不使用)
        ↓
③(人の目でJSONをレビュー)
        ↓
④write_to_notion.py — Notionへ一括書き込み (スクリプト実行の許可は1回だけ)
```

## 全体の流れ（.enex形式の場合）

```
①Evernoteから.enexをエクスポート
        ↓
②parse_enex.py    — 本文を段落単位に分解 + 添付メディア抽出 (LLM不使用)
        ↓
③classify.py       — 段落を項目に分類 (Anthropic APIキーで実行。Claude Codeの利用枠は消費しない)
        ↓
④(人の目でJSONをレビュー)
        ↓
⑤write_to_notion.py — Notionへ一括書き込み (スクリプト実行の許可は1回だけ)
```

**設計上の最重要ポイント（.enex経路）**: `classify.py` はLLMに「本文を書き写させません」。
段落ごとに番号を振り、モデルには「何番の段落がどの項目か」だけを答えさせ、
実際のテキストは元の段落をそのままスクリプト側で連結します。
これにより、以前の手動移行(若林良樹さん分)で発生した「LLMが書き写す際の文字化け」を
仕組みとして起こりえなくしています。HTML形式の経路はそもそもLLMを使わないため、この問題が発生しません。

## 事前準備

### 1. Evernoteからエクスポート

**HTML形式（推奨・まずはこちらを試してください）**: Evernoteで対象者のノートブックを開き、
複数ノートを選択（またはノートブック全体を選択）→右クリック→「エクスポート」→
「HTML形式」を選択してエクスポートします。`<氏名>.html` というファイルと、
写真などの添付がある場合は `<氏名> files` というフォルダが一緒に出力されます。
**この2つ（ファイルとフォルダ）は必ず同じ場所に置いたままにしてください**（写真の参照が壊れます）。

**.enex形式**: Evernoteアプリで対象の人のノートブック（またはタグで絞り込んだノート群）を選択し、
「エクスポート」→「Evernote XML形式 (.enex)」で書き出してください。

いずれも1人1ファイルが基本です。

### 2. 依存パッケージ

```bash
cd scripts/migrate
pip3 install -r requirements.txt
```

### 3. 環境変数

このアプリの `.env.local`（`NOTION_TOKEN` / `NOTION_DATABASE_ID` / `NOTION_MEMBERS_DATABASE_ID`）を
そのまま読み込みます。**.enex経路を使う場合のみ**、追加で **Anthropic APIキー**が必要です:

```bash
# .env.local に追記するか、実行時にexport
export ANTHROPIC_API_KEY=sk-ant-...
```

> Anthropic APIキーは https://console.anthropic.com/ で発行できます。
> Claude Codeのサブスクリプション利用枠(5時間/週制限)とは別の従量課金なので、
> ここで大量に呼び出してもClaude Codeの制限には影響しません。
> デフォルトモデルは `claude-haiku-4-5-20251001`（低コスト）です。
> 分類精度に問題があれば `--model claude-sonnet-5` で精度を上げられます。

## 使い方（HTML形式・推奨）

### ステップ1: パース（分類済みJSONを直接出力）

```bash
python3 parse_html_export.py "若林良樹/若林良樹.html" --person "若林良樹"
```

`data/classified/若林良樹.json` が直接出力されます（LLMを使わないので分類ステップは不要です）。

表形式に一致しないノート（初回問診票など）があった場合は
`data/classified/若林良樹_unhandled.json` に内容が保存され、警告が表示されます。
これらは自動でNotionに書き込まれないので、必要なら手動で選手プロフィールなどに反映してください。

### ステップ2: レビュー

`data/classified/若林良樹.json` はただのJSONなので、エディタで直接開いて確認・修正できます。
表からそのまま抜き出しているだけなので基本的に文字化けの心配はありませんが、
セッションによっては同じ日付で内容が異なる複数レコードが存在することがあります
（例: 通常セッションとは別枠で書かれた怪我の経過報告など）。これは実データで確認された
正常なパターンなので、`write_to_notion.py` 側も日付だけでなく主訴の内容まで見て
重複判定するようになっています。

修正が必要な場合はJSONを直接編集してください（このファイルがそのままステップ3の入力になります）。

### ステップ3: Notionへ書き込み

まずdry-run（実際には書き込まない）で内容を確認:

```bash
python3 write_to_notion.py data/classified/若林良樹.json
```

問題なければ `--commit` を付けて実行します。**許可プロンプトはこのコマンド実行時の1回だけです**:

```bash
python3 write_to_notion.py data/classified/若林良樹.json --commit
```

実行後、選手ごとの総レコード数が表示されるので、想定件数と一致するか確認してください。
同じコマンドを再実行しても、既に存在する（選手×施術日×主訴が一致する）レコードは
自動的にスキップされるため、重複作成の心配なく再実行できます。

## 使い方（.enex形式）

### ステップ1: パース

```bash
python3 parse_enex.py path/to/若林良樹.enex --person "若林良樹" --out-dir data/parsed
```

`data/parsed/若林良樹.json`（段落リスト）と `data/parsed/若林良樹_resources/`（添付ファイル実体）が出力されます。

### ステップ2: 分類

まずは少数件でテストすることを推奨します:

```bash
python3 classify.py data/parsed/若林良樹.json --limit 3
```

`data/classified/若林良樹.json` を開き、`trainerName` / `location` / `tags` が
正しい候補から選ばれているか、`chiefComplaint` などの項目分けが妥当かを確認してください。
問題なければ `--limit` を外して全件処理します:

```bash
python3 classify.py data/parsed/若林良樹.json
```

### ステップ3: レビュー

`data/classified/若林良樹.json` はただのJSONなので、エディタで直接開いて確認・修正できます。
各レコードには `rawParagraphs`（元の段落全部）も残しているので、
「この項目分けで合っているか」を元の文章と見比べながら確認できます。

修正が必要な場合はJSONを直接編集してください（このファイルがそのままステップ4の入力になります）。

### ステップ4: Notionへ書き込み

HTML形式の場合と同じです（上記「使い方（HTML形式・推奨）」のステップ3を参照）。

## メディア（写真・動画）について

`write_to_notion.py` は現時点では **メディアファイルのアップロードは行いません**
(Notionの「メディア」プロパティは外部URLを参照する仕組みのため、
どこかにホスティングして公開URLを発行する必要があり、
アプリ側は Vercel Blob を使っていますがPythonから安全に検証できていないため見送りました)。

添付ファイルの実体は、HTML形式の場合は `<氏名> files/` フォルダに、.enex形式の場合は
`data/parsed/<person>_resources/` に保存されているので、必要な記録についてはアプリの
「編集」画面から手動で添付してください。

## 複数人をまとめて処理する場合（batch_migrate.py）

HTML形式なら、数十人分でも1つのコマンドで通しで処理できます。
Evernoteでエクスポートした「`<氏名>`フォルダ（`<氏名>.html` + `<氏名> files/`）」を、
そのまま1つの親フォルダにまとめて置いてください:

```
imports/
  中村海斗/
    中村海斗.html
    中村海斗 files/
  若林良樹/
    若林良樹.html
    若林良樹 files/
  ...
```

まずは1人だけ試して動作を確認することをおすすめします:

```bash
python3 batch_migrate.py imports/ --only 中村海斗
```

全員分をdry-runで確認:

```bash
python3 batch_migrate.py imports/
```

問題なければ `--commit` を付けて全員分を本番書き込みします（**許可プロンプトはこのコマンド
実行時の1回だけです**）:

```bash
python3 batch_migrate.py imports/ --commit
```

最後に人ごとの結果（作成件数・重複スキップ件数・エラーの有無）が一覧表示されます。
`[要確認]` と表示された人は、部員DBに氏名が見つからなかった等の理由でスキップされている
ので、個別に `python3 write_to_notion.py data/classified/<氏名>.json` を実行して詳細を確認してください。

内部的には人ごとに `parse_html_export.py` → `write_to_notion.py` を順番に実行しているだけなので、
1人だけ個別にやり直したい場合は、これまで通り各スクリプトを直接実行しても構いません。

### 自動で行われるデータクレンジングについて

`write_to_notion.py`（`batch_migrate.py`経由でも同様）は、書き込み前に以下を自動で行います:

- **選手名の空白ゆれを吸収**: エクスポート元のフォルダ名が「中村海斗」でも、部員DBの登録名が
  「中村　海斗」のように全角スペース区切りであれば、空白を無視して同一人物と判定し、
  実際に書き込む氏名は部員DB側の正式な登録名に統一します。
- **担当トレーナー名のクレンジング**: 実データには「担当」欄に会議メモやLINE連絡、複数トレーナーの
  併記など、実際のトレーナー名ではない記載が混ざっていることがありました。Notion側に既に
  登録されている選択肢（中野・古谷・木村など）と一致しない値は自動的にmemoへ退避し、
  担当トレーナー名は空欄にします（情報は失われず、選択肢だけがクリーンに保たれます）。

## トラブルシューティング

- **「部員」DBに選手が見つからない**: `write_to_notion.py` が候補となりそうな名前を
  提示します。Notion側の表記揺れ（旧字体・スペースの有無など）を確認してください。
- **レート制限 (429)**: `notion_request` / `anthropic_messages` はどちらも自動リトライします。
  頻発する場合は `write_to_notion.py --sleep` を増やしてください。
- **分類結果のJSONパースに失敗（.enex経路）**: モデルが余計な説明文を含めて返した場合に発生します。
  再実行するか、`--model claude-sonnet-5` に切り替えてみてください。
- **HTML形式で「セッション表の形式に一致しない」と表示される**: そのノートは表形式ではない
  （初回問診票など）か、行ラベルの表記が想定と異なる可能性があります。
  `data/classified/<氏名>_unhandled.json` の中身を確認し、必要なら`parse_html_export.py`の
  `ROW_LABEL_MAP`を実際の表記に合わせて調整してください。
